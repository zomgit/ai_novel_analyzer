# Workspace 项目处理完整指南

## 📋 概述

Workspace 是一个基于文件系统的书籍分析项目管理系统，通过简单的文件夹结构即可管理多个书籍项目的拆分和分析。

**核心特点：**
- 📁 **文件系统即数据库** - 无需维护复杂的状态表，目录结构就是状态
- ⚡ **极简操作** - 三个脚本完成拆书、分析、进度查询
- 🔒 **血缘追踪** - 每个章节 JSON 包含完整的项目/书名/卷目信息
- ♻️ **幂等设计** - 重复运行自动跳过已处理章节

---

## 🏗️ 目录结构规范

### 基础布局

```
workspace/                           # 工作区根目录（由配置自动生成）
├── projects/                        # 项目集合
│   └── {项目名称}/                  # 每个项目一个文件夹
│       ├── project_meta.json        # 项目元数据
│       └── {书名}/                  # 每本书一个文件夹
│           ├── book_meta.json       # 书籍元数据
│           ├── source/              # 原始文本副本（仅溯源）
│           │   └── 原文件名.txt
│           └── vol_{NNN}_{卷名}/    # 每个卷目一个文件夹
│               ├── volume_meta.json # 卷元数据
│               ├── chap_0001.txt    # 章节源文本
│               └── chap_0001.json   # AI 分析结果（配对即已处理）
└── db/                              # 数据库 + 向量库
    ├── novel_analyzer.db            # SQLite（可选）
    └── chromadb/                    # ChromaDB（可选）
```

### 命名规则

| 层级 | 命名规范 | 示例 |
|------|---------|------|
| 项目名 | 任意字符串，避免特殊字符 | `我的小说集` |
| 书名 | 任意字符串 | `重生之门` |
| 卷目 | `vol_{编号 3 位补零}_{卷名}` | `vol_001_第一册` |
| 章节 | `chap_{编号 4 位补零}.txt/json` | `chap_0001.txt` |

## 🛠️ 三步操作流程

### 第一步：拆书（split_book.py）

将单本/txt 小说分割为章节，生成三级 JSON 元数据。

#### 命令格式

```bash
uv run python scripts/split_book.py \
    -i 原始文本路径 --project 项目名 --book 书名 --author 作者名 [选项]
```

#### 必填入参

| 参数 | 说明 | 示例 |
|------|------|------|
| `-i, --input` | 原始 txt 文件路径 | `novel.txt` |
| `--project` | 所属项目名（不存在则新建） | `仙侠小说集` |
| `--book` | 书名（必填，不从文件名猜测） | `长生诀` |
| `--author` | 作者名（未知可填"佚名"） | `张三丰` |

#### 常用选项

```bash
--volume-title "第一章卷"          # 原文未识别分卷时的卷名
--volume-number 2                  # 手动指定卷号（默认 1）
--dimension-config "xianxia.yaml" # 维度配置（默认 xianxia）
--fallback-chars 5000             # 无章节标题时切分粒度
--preview                          # 预览模式：只展示不写入
--overwrite                        # 允许覆盖已存在的卷目录
```

#### 典型用例

```bash
# 1. 预览分割效果（不产生任何文件）
uv run python scripts/split_book.py \
    -i data/raw/某小说.txt \
    --project "古典文学" \
    --book "三国演义" \
    --author "罗贯中" \
    --preview

# 2. 实际执行拆书（自动创建目录与 JSON 元数据）
uv run python scripts/split_book.py \
    -i data/raw/某小说.txt \
    --project "古典文学" \
    --book "三国演义" \
    --author "罗贯中" \
    --overwrite

# 3. 原文有多卷时手动指定
uv run python scripts/split_book.py \
    -i data/raw/某小说.txt \
    --project "科幻系列" \
    --book "三体Ⅰ" \
    --author "刘慈欣" \
    --volume-number 1 \
    --volume-title "地球往事"
```

#### 输出的关键文件

- ✅ `project_meta.json` - 项目索引（books 列表追加新书）
- ✅ `book_meta.json` - 书籍元数据（记录 author/source_files/volumes）
- ✅ `volume_meta.json` - 卷元数据（chapters 初始状态全部 pending）
- ✅ `source/{原文件名}` - 原始 txt 副本（仅作溯源，不参与后续流程）
- ✅ `chap_XXXX.txt` - 分割后的章节源文本（与 JSON 配对存放）

### 第二步：批量分析（batch_processor.py）

对指定卷目录下所有未处理的章节进行 AI 分析。

#### 命令格式

```bash
uv run python scripts/batch_processor.py \
    <卷目录路径> [选项]
```

#### 必选参数

| 参数 | 说明 |
|------|------|
| `<卷目录>` | split_book.py 产出的卷目录路径（必须含 volume_meta.json） |

#### 常用选项

```bash
--workers N                      # 并行 worker 数（默认 4）
--continue-on-failure            # 单章失败继续下一章节
--no-vector-db                   # 禁用向量库写入
--vector-db-path ./custom/       # 自定义向量库路径
--api-key KEY                    # Embedding API Key（临时）
--config-file config/prod.yaml   # 指定配置文件
```

**注意：** 默认始终显示每章的 token 消耗与耗时（不可关闭），无需额外参数。

#### 智能特性

1. **幂等跳过** - 已生成 `chap_XXX.json` 且 status=processed 的章节自动跳过
2. **失败重试** - status=failed 的章节会自动重新处理
3. **血缘注入** - 章节 JSON 前部插入 `chapter_identity` 血缘块（来自 volume_meta）
4. **状态回写** - 批末统一更新 volume_meta.json 的章节状态数组

#### 典型用例

```bash
# 1. 分析单个卷（最快启动方式）
uv run python scripts/batch_processor.py \
    workspace/projects/古典文学/三国演义/vol_001_第一册

# 2. 分析多个卷（分别调用）
uv run python scripts/batch_processor.py \
    workspace/projects/古典文学/三国演义/vol_002_第二册
    
# 3. 禁用向量库（仅保存 JSON）
uv run python scripts/batch_processor.py \
    workspace/projects/古典文学/三国演义/vol_001_第一册 \
    --no-vector-db
    
# 4. 高并发模式
uv run python scripts/batch_processor.py \
    workspace/projects/古典文学/三国演义/vol_001_第一册 \
    --workers 8 \
    --continue-on-failure
```

#### 输出日志关键信息

```text

Skipped 2 already-processed chapters        ← 幂等跳过统计
Found 5 pending chapters to process         ← 待处理数量
Processing chapter chap_0003                ← 正在处理
✅ Chapter chap_0003: Success | 8,543 tokens (6,521 p + 2,022 c) | 15.32s
...
BATCH PROCESSING COMPLETED
Total chapters:     7                       ← 总章节数
Successful:         6                       ← 成功数
Failed:             1                       ← 失败数
Success rate:       85.71%                  ← 成功率

```

**Token 统计说明：**
- `8,543 tokens` - 本章总消耗（prompt + completion）
- `6,521 p` - prompt 输入 tokens
- `2,022 c` - completion 输出 tokens
- `15.32s` - 单章处理耗时

### 第三步：进度查询（check_progress.py）

递归扫描项目目录，输出各卷的处理进度报告。

#### 命令格式

```bash
uv run python scripts/check_progress.py [目标目录]
```

#### 参数说明

| 参数 | 说明 |
|------|------|
| `[target]` | 可选：指定项目目录路径（缺省扫描整个 workspace/projects） |

#### 输出样式

```text
================================================================
📁 项目：三国演义    维度配置：xianxia.yaml
================================================================

  📖 三国演义（作者：罗贯中）
     📚 vol_001_第一册                         10/20 (50.0%)
        ⏳ 待处理 10
        ❌ 失败 2

================================================================
总计：10/20 章已处理 (50.0%)
  ⏳ 待处理：10
  ❌ 失败（重跑 batch_processor.py 即可重试）：2
================================================================
```

#### 状态图例

- `✅ processed` - 已成功分析并写出 JSON
- `⏳ pending` - 只有 txt 未处理（或 json 损坏）
- `❌ failed` - 分析失败后重试中
- `🔄 other` - 异常状态（建议检查 JSON 内容）

## 📊 JSON Schema 参考

### 1. project_meta.json

```json
{
  "project_name": "古典文学",
  "description": "",
  "dimension_config": "xianxia.yaml",
  "books": ["三国演义", "水浒传"],
  "created_at": "2026-08-17T10:30:00+00:00",
  "updated_at": "2026-08-17T14:20:00+00:00"
}
```

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| project_name | string | ✅ | 与目录名一致 |
| dimension_config | string | ✅ | 引用的维度配置文件名 |
| books | array[string] | ✅ | 书名列表（动态追加） |
| description | string | 可选 | 项目描述 |
| created_at / updated_at | datetime | ✅ | ISO8601 UTC 时间戳 |

---

### 2. book_meta.json

```json
{
  "book_name": "三国演义",
  "author": "罗贯中",
  "source_files": ["source/original_novel.txt"],
  "volumes": ["vol_001_第一册", "vol_002_第二册"],
  "created_at": "2026-08-17T11:00:00+00:00",
  "updated_at": "2026-08-17T11:05:00+00:00"
}
```

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| book_name | string | ✅ | 与目录名一致 |
| author | string | ✅ | 作者名（未知填"佚名"） |
| source_files | array[string] | 可选 | 原始 txt 文件相对路径 |
| volumes | array[string] | ✅ | 卷目录名列表（动态追加） |

---

### 3. volume_meta.json

```json
{
  "project_name": "古典文学",
  "book_name": "三国演义",
  "volume_number": 1,
  "volume_title": "第一册",
  "chapters": [
    {"number": 1, "title": "第一回 黄巾起义", "status": "processed"},
    {"number": 2, "title": "第二回 桃园结义", "status": "pending"}
  ],
  "created_at": "2026-08-17T11:00:00+00:00",
  "updated_at": "2026-08-17T14:20:00+00:00"
}
```

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| project_name/book_name | string | ✅ | **血缘快照**（即使卷目录被复制仍保留） |
| volume_number | int | ✅ | 卷编号（1~999） |
| volume_title | string | ✅ | 卷名 |
| chapters | array[object] | ✅ | 章节列表（动态更新 status） |

**chapters[].status 枚举值：**
- `pending` - 待处理（仅有 txt）
- `processing` - 处理中（临时状态）
- `processed` - 已成功（已有配对 JSON）
- `failed` - 失败（需重试，可附带 error 字段）

---

### 4. 章节分析 JSON（chap_XXXX.json）

```json
{
  "chapter_identity": {
    "project_name": "古典文学",
    "book_name": "三国演义",
    "volume_number": 1,
    "volume_title": "第一册",
    "chapter_number": 1,
    "chapter_title": "第一回 黄巾起义"
  },
  "source_file": "chap_0001.txt",
  "processed_at": "2026-08-17T14:20:00+00:00",
  "status": "processed",
  "metadata": {...},
  "characters": [...],
  "world_events": [...],
  ...
}
```

**关键字段说明：**

| 字段 | 类型 | 来源 | 说明 |
|------|------|------|------|
| chapter_identity | object | **自动注入** | 血缘信息块（来自 volume_meta） |
| source_file | string | **自动填充** | 同目录 txt 文件名 |
| processed_at | datetime | **自动填充** | UTC 处理完成时间 |
| status | string | **自动填充** | processed/failed |
| metadata/characters/events | object | AI 分析结果 | 原有七维分析字段保持不变 |

## 💡 常见场景指引

### 场景 1：多卷本小说分册处理

```bash
# 1. 原文有分卷标记 → 自动识别为多个卷目
uv run python scripts/split_book.py \
    -i "长篇小说.txt" \
    --project "我的作品" \
    --book "天龙八部" \
    --author "金庸" \
    
# 输出目录结构：
# vol_001_逐日篇/
# vol_002_苍生篇/
# vol_003 _天下篇/

# 2. 分别对各卷执行分析
uv run python scripts/batch_processor.py workspace/projects/我的作品/天龙八部/vol_001_逐日篇
uv run python scripts/batch_processor.py workspace/projects/我的作品/天龙八部/vol_002_苍生篇
uv run python scripts/batch_processor.py workspace/projects/我的作品/天龙八部/vol_003_天下篇
```

### 场景 2：旧数据迁移

用户遗留的 `user_data/novel_raw/` 和 `processed/` 可按需迁移至新结构。暂不提供自动化迁移工具，手动操作建议：

```bash
# 以单卷为单位逐步迁移
for file in user_data/novel_raw/*.txt; do
    uv run python scripts/split_book.py \
        -i "$file" \
        --project "迁移项目" \
        --book "$(basename "$file")" \
        --author "未知"
done

# 再对迁移后的卷执行 analysis
```

### 场景 3：书籍跨项目移动

```bash
# 直接移动文件夹，同步更新 project_meta.json
mv workspace/projects/项目 A/某书/ workspace/projects/项目 B/某书/

# 手动编辑两处 project_meta.json：
# - 项目 A: books: remove("某书")
# - 项目 B: books: append("某书")

# 章节 JSON 中的 project_name 保留历史快照，不回改
```

## ⚙️ 配置管理

### defaults.yaml 关键项

```yaml
workspace:
  root: "workspace"                          # 工作区根目录
  projects_dir: "workspace/projects"         # 项目集合目录
  
db:
  path: "workspace/db"                       # SQLite + ChromaDB 根目录
  
logging:
  log_dir: "logs"                            # 日志目录
```

### production.yaml 推荐修改

如需个性化配置（如自定义数据库位置），可在 `production.yaml` 中覆盖对应键：

```yaml
workspace:
  root: "./my_workspace"                     # 覆盖工作区根

db:
  path: "./external_db"                      # 自定义数据库路径
```

注意：配置变更可能导致目录重建，建议先备份 `workspace/`。

## 🚀 最佳实践建议

1. **拆书前先预览** - 始终先用 `--preview` 检查分节是否合理
2. **卷名尽量具体** - `vol_001_第一部` 比 `vol_001_单册` 更易读
3. **定期查看进度** - 用 `check_progress.py` 宏观掌控进度，避免遗漏
4. **失败章节及时重试** - status=failed 的会累积，建议每次分析前清理失败状态
5. **备份卷目录** - 重要章节分析可定期 cp 一份到归档目录

## 🆘 故障排查

### Error: 缺少必需配置项 logging.log_dir

**原因：** 配置文件缺失导致 ConfigManager 报错  
**解决：** 确保 `defaults.yaml` 或 `production.yaml` 存在且包含 `logging.log_dir`

### Skipped X already-processed chapters

**正常现象：** 表示 X 个章节已在上一轮分析中处理完成，幂等机制生效  
**处理：** 无需担心，除非怀疑 JSON 已损坏可手动删除后重跑

### 中文乱码或控制台崩溃

**原因：** Windows GBK 编码兼容性问题  
**解决：** 已在脚本头部添加 `sys.stdout.reconfigure(encoding='utf-8')`，若仍有问题请升级 Python 版本至 3.7+

### chapter_identity 字段为空

**原因：** 可能来自旧版 JSON 或非 split_book.py 产出的源文件  
**处理：** 重新运行 `split_book.py` 生成标准结构后分析即可
